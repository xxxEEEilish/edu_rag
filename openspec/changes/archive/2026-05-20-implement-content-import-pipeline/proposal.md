## Why

教育 RAG 服务已经具备基础项目骨架、配置、Schema 和外部服务适配边界，但还缺少将课程资料、项目文档、DOCX 讲义和题库内容真正写入知识库的导入闭环。该变更用于补齐一期最小可用链路，让后续检索、问答和后台管理能够依赖可追踪、可复核的内容资产。

## What Changes

- 新增内容导入流水线，支持创建导入任务、上传或登记原始文件、解析文本内容、生成知识片段、计算向量并写入持久化存储。
- 新增任务状态追踪能力，导入过程应记录 `pending`、`processing`、`completed`、`failed`、`canceled` 等生命周期状态、进度、错误信息和元数据。
- 新增文档解析边界，首期覆盖可检索文本文件、Markdown、DOCX 和结构化题库数据，并为 PDF、课件、字幕和多模态资源预留扩展入口。
- 新增内容幂等与追踪规则，基于文件、内容哈希、租户和元数据生成稳定记录，避免重复入库并保留来源文件、章节、课程、项目和知识点信息。
- 新增导入 API 和服务编排层，允许客户端提交导入请求、查询任务状态，并在外部依赖不可用时返回清晰失败原因。
- 新增单元测试和离线替身，验证流水线编排、状态变更、解析结果、切片结果和失败处理，不依赖真实 MongoDB、Milvus、MinIO 或模型服务。

## Capabilities

### New Capabilities

- `content-import-pipeline`: 覆盖教育内容导入任务、原始文件存储、文档解析、知识切片、向量化、入库、状态查询、失败记录和可追踪元数据。

### Modified Capabilities

- `edu-rag-foundation`: 扩展 foundation 中已定义的占位导入 Schema 和外部服务适配边界，使其具备面向导入流水线的具体行为约束。

## Impact

- Affected code: `api/` 新增导入路由，`services/` 新增导入编排服务，`processor/` 新增解析、清洗、切片处理器，`utils/` 补齐 MongoDB、Milvus、MinIO、Embedding 适配调用边界，`schema/` 扩展导入请求、任务状态和解析结果模型。
- APIs: 新增内容导入提交接口、任务状态查询接口，可能新增取消任务或重试任务接口。
- Dependencies: 可能引入 DOCX 解析库、文件类型检测或文本清洗依赖；向量化、对象存储和数据库仍通过现有配置与适配器边界接入。
- Systems: MongoDB 用于任务和元数据，MinIO 用于原始文件，Milvus 用于向量片段，Embedding 服务用于向量生成；测试环境必须可通过内存替身离线运行。
