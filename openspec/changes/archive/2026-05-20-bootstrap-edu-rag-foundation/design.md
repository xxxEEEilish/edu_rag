## Context

当前仓库已有教育知识库需求分析、方案设计和 OpenSpec 开发顺序规划，但还没有可运行的 Python 后端工程。后续内容导入、存储索引、检索问答、会话流式输出和最小页面联调都依赖统一的配置、数据模型、目录结构和外部系统适配边界。

本变更是一期 MVP 的第一个阶段，目标是搭建基础工程骨架，而不是实现完整业务链路。实现时需要为 MongoDB、Milvus、MinIO、LLM、Embedding、Reranker、DOCX 解析等后续能力预留清晰接口，但本阶段不要求真实连通外部服务。

## Goals / Non-Goals

**Goals:**

- 建立符合方案设计的 FastAPI 项目骨架和核心目录。
- 提供可本地启动的应用入口和健康检查接口。
- 通过 `.env.example` 和 `core/config.py` 统一管理应用、模型、向量库、文档库、对象存储和 DOCX 解析配置。
- 在 `core/enums.py` 中定义后续链路共用的内容类型、任务状态、查询意图和来源类型。
- 在 `schema/` 中定义基础 Pydantic 模型，包括 `KnowledgeChunk`、`Question`、`ImportTask`、`QueryRequest`、`QueryResponse` 和引用来源模型。
- 在 `utils/` 中提供外部依赖适配层占位，后续变更可在不改 API/Schema 的情况下接入真实实现。
- 提供基础单元测试，覆盖配置加载、健康检查和核心 Schema 构造。

**Non-Goals:**

- 不实现真实文件上传、解析、切片、向量化或入库流程。
- 不连接真实 MongoDB、Milvus、MinIO 或模型服务。
- 不实现检索、RRF、Rerank、答案生成、SSE 或会话历史。
- 不实现正式前端页面，只创建目录或占位入口。
- 不实现后台管理、权限、多租户、视频检索或多模态检索。

## Decisions

### 使用 FastAPI 作为后端入口

项目采用 FastAPI + Uvicorn 作为一期后端入口。它与方案设计一致，天然支持异步接口、Pydantic 校验和后续 SSE 扩展。

备选方案是 Flask 或纯脚本入口。Flask 的类型校验和 OpenAPI 生成能力弱于 FastAPI；纯脚本不利于后续导入、查询、状态查询等 HTTP API 分阶段扩展。

### 配置集中在 `core/config.py`

所有环境变量通过 `core/config.py` 读取，并提供一个可复用的 `Settings` 对象。`.env.example` 作为配置契约，必须覆盖后续阶段会依赖的模型、向量库、文档库、对象存储、端口和 DOCX 解析参数。

备选方案是在各工具模块中直接读取环境变量。该方式短期简单，但会造成配置分散，后续测试和部署更难控制。

### Schema 先定义稳定业务边界

基础 Schema 只覆盖后续链路会共同依赖的数据边界：知识片段、题目、导入任务、查询请求、查询响应和引用来源。字段需要兼顾一期必需字段和后续扩展字段，例如 `tenant_id`、`version`、`content_hash`、`is_active`。

备选方案是等到各阶段实现时再分别定义模型。该方式会降低初始工作量，但容易导致导入、索引、检索和页面之间字段不一致。

### 外部依赖先提供适配层占位

`utils/` 中的 LLM、Embedding、Reranker、MongoDB、Milvus、MinIO 工具模块只建立类、函数签名和清晰异常提示，不在本阶段强制安装或连接外部服务。后续变更可以替换占位实现或补充真实客户端。

备选方案是在第一阶段直接集成所有外部依赖。这样会扩大阶段 1 的范围，也会让本地启动受数据库、向量库和模型凭据影响。

### 测试优先覆盖基础契约

本阶段测试集中在配置加载、健康检查和核心 Schema 构造。它们是后续阶段最容易受影响的公共契约，应在项目骨架建立时就固定下来。

备选方案是只创建文件不写测试。这样虽然更快，但无法验证项目是否可启动、配置是否可加载、Schema 是否能被后续链路复用。

## Risks / Trade-offs

- 外部依赖仅占位，可能与后续真实客户端存在签名差异 -> 通过简洁接口和单一适配层隔离，后续变更只改工具模块内部。
- 预留字段过多会增加模型复杂度 -> 只保留需求和方案中明确提到的扩展字段，例如租户、版本、内容哈希和启用状态。
- 第一阶段目录较多但业务实现较少 -> 用 README 或占位文件保持目录可见，同时避免提前写入未验证业务逻辑。
- Windows 与 Linux 环境变量和路径行为不同 -> 使用 `pathlib.Path` 和配置测试覆盖基础路径构造。

## Migration Plan

这是新仓库的首个工程化变更，不涉及历史数据迁移。实现后应可以通过安装依赖、复制 `.env.example` 为 `.env` 并运行 FastAPI 应用来验证基础启动。

如需回滚，可删除本变更新增的项目骨架、配置、Schema、工具占位和测试文件，不影响现有需求与方案文档。

## Open Questions

- DOCX 解析的一期真实实现采用 `python-docx` 作为主路径，是否还需要同时引入 Mammoth 作为语义保真备选。
- 依赖管理采用 `requirements.txt` 还是迁移到 `pyproject.toml`；本阶段可先选择轻量且兼容当前规划的方式。
